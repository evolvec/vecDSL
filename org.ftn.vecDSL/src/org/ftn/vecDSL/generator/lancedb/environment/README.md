# LanceDB: embedded deployment

Generated by vecDSL for {{product}} {{lancedb.version}} (Lance {{lance.version}}, {{license}}).

There is no server to start. LanceDB open source is a library that runs inside each generated program and keeps every
table as a Lance dataset (a directory of Arrow-compatible data files and versioned manifests) under one storage URI:

- `{{storage.variable}}`: the storage URI. Default `{{storage.uri}}`, a directory relative to the working directory of the
  program, created on first use. An absolute path works too (Windows paths with backslashes and spaces included).
  Object-store URIs (`s3://`, `gs://`, `az://`) are accepted by the SDKs but the generated programs are not tested on them.
- A logical database is a sub-directory of the storage URI.
- Several processes may write to one directory: each write is a commit of a new table version with optimistic
  concurrency (a conflicting commit is retried or fails); the programs check for newer versions before every read
  (read consistency interval 0).

To start over, delete the storage directory.

Languages:

- Python: `pip install -r python/requirements.txt` (lancedb {{sdk.python.min}}, Python >= {{python.min}}; wheels for
  Windows, Linux and macOS), then `python -u python/<program>.py`.
- TypeScript: `npm install`, `npm run build`, `npm start` in `typescript/` (@lancedb/lancedb {{sdk.typescript.version}},
  Node.js >= {{node.min}}).
- Java: Maven project in `java/` with the Lance Java SDK ({{sdk.java.group}}:{{sdk.java.artifact}} {{lance.version}}). Its JNI
  library ships for {{java.native}} only, so on Windows run the Java program in a Linux container or WSL. Arrow needs
  `MAVEN_OPTS=--add-opens=java.base/java.nio=ALL-UNNAMED` on Java 17, then `mvn compile exec:java` in `java/`, for example
  `docker run --rm -e MAVEN_OPTS=--add-opens=java.base/java.nio=ALL-UNNAMED -v <generated folder>:/gen -w /gen/java
  maven:3.9-eclipse-temurin-17 mvn -q -B compile exec:java`.
