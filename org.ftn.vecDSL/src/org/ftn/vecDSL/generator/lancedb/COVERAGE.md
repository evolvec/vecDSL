# vecDSL coverage: LanceDB

LanceDB OSS 0.41.0 over Lance 14.0.2 (29 Oct 2026, Apache 2.0), embedded: the library runs inside each generated program over a directory of Lance datasets (storage URI `VECDSL_LANCEDB_URI`, default `lancedb-data`), with no server. Python `lancedb` 0.41.0 to <0.42 (Python 3.10 or later), TypeScript `@lancedb/lancedb` 0.41.0 with `apache-arrow` 21.2.0 (Node.js 22 or later), Java `org.lance:lance-core` 14.0.2 (the Lance Java SDK; the lancedb Java SDK reaches LanceDB Cloud and Enterprise only) with Arrow Java 18.3.0; versions checked on 2026-11-14. Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (one LanceDB or Lance operation, or a fixed sequence the SDKs offer for the construct), concealed (operations that compose LanceDB features into the exact vecDSL semantics, or runtime work over their results), unsupported (LanceDB open source or the embedded deployment lacks it; the generator raises the message), not-applicable (cannot occur for LanceDB). Where a language differs, its column says so. Rows whose notes start with "generation pending" are native or concealed in LanceDB but not generated yet; they raise "... has no LanceDB mapping yet". Every table schema, where string, update expression, index plan and search plan is built by the generator (`LancedbStatements.xtend`, `LancedbSchema.xtend`, `LancedbFilter.xtend`, `LancedbSql.java`, `LancedbTable.java`) and executed by `vecdsl_lancedb_runtime.py`, `vecdslLancedbRuntime.ts` or `LancedbRuntime.java`, so the three programs write the same Lance files; values in where strings are quoted literals or runtime-bound parameters with the same quoting rules.
