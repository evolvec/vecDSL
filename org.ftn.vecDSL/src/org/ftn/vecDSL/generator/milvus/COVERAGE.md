Server 3.0.4 (`milvusdb/milvus:v3.0.4` with etcd and MinIO), Python `pymilvus` 3.0.2 to <3.1, TypeScript `@zilliz/milvus2-sdk-node` 3.0.6, Java `io.milvus:milvus-sdk-java` 3.0.12 (pins unchanged on 2026-11-10; server 3.0.6, pymilvus 3.0.3 and no newer Node or Java release exist, and no construct needed them). Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (one SDK or REST call), concealed (the runtime composes documented calls with the exact vecDSL semantics), unsupported (Milvus lacks it; the generator raises the message), not-applicable (cannot occur for Milvus). Rows marked "generation pending" are native or concealed in Milvus but not generated yet; the generator raises "... has no Milvus mapping yet" for them. Runtime calls go through `vecdsl_milvus_runtime.py`, `vecdslMilvusRuntime.ts` or `MilvusRuntime.java`; "REST" means the runtime calls the RESTful API v2 because an SDK has no call for it.
