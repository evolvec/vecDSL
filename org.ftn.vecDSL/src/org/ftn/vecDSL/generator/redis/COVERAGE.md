# vecDSL coverage: Redis

Redis Open Source 8.10.3 (`redis:8.10.3-trixie`, the official image with the bundled Query Engine RediSearch v8.10.1 and JSON v8.10.0, port 6379 on 127.0.0.1, append-only persistence in the named volume on `/data`), Python `redis` 8.1.0 to <8.2, TypeScript `redis` (node-redis) 6.3.1, Java Jedis 8.0.2 with Gson 2.14.0 (versions checked on 2026-11-12). Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (one Redis command or a fixed command sequence Redis offers for the construct), concealed (commands that compose Redis features into the exact vecDSL semantics, or runtime work over their replies), unsupported (Redis Open Source, its license or this deployment lack it; the generator raises the message), not-applicable (cannot occur for Redis). Rows whose notes start with "generation pending" are native or concealed in Redis but not generated yet; they raise "... has no Redis mapping yet". Every command argument array is built by the generator (`RedisIndex.java`, `RedisQuery.java`, `RedisStatements.xtend`) and sent by `vecdsl_redis_runtime.py`, `vecdslRedisRuntime.ts` or `RedisRuntime.java`, so the three programs send identical commands; values are PARAMS or separate arguments, never part of a query string. Collections are FT indexes over JSON documents (Query Engine model); vector sets are not used.
