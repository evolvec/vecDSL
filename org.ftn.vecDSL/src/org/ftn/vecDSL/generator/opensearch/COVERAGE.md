Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (a REST API, query, mapping or plugin construct OpenSearch offers for the construct), concealed (requests or runtime logic that compose OpenSearch features into the exact vecDSL semantics), unsupported (OpenSearch, its bundled plugins or the single-node deployment lacks it; the generator raises the message), not-applicable (cannot occur for OpenSearch). Rows whose notes start with "generation pending" are native or concealed in OpenSearch but not generated yet; they raise "... has no OpenSearch mapping yet". Every request body is built by the generator (`OpenSearchStatements.xtend`, `OpenSearchSchema.xtend`, `OpenSearchFilter.xtend`, `OpenSearchBodies.java`) and sent by `vecdsl_opensearch_runtime.py`, `vecdslOpenSearchRuntime.ts` or `OpenSearchRuntime.java`, so the Python, TypeScript and Java programs send the same requests.
