Server 1.20.0 (`qdrant/qdrant:v1.20.0`, REST 6333, gRPC 6334), Python `qdrant-client` 1.20.0 to <1.21, TypeScript `@qdrant/js-client-rest` 1.20.0, Java `io.qdrant:client` 1.20.0 (gRPC; pins unchanged on 2026-11-10: 1.20.0 is the latest server tag, PyPI release, npm `latest` and java-client tag). Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (one SDK or REST call), concealed (the runtime composes documented calls with the exact vecDSL semantics), unsupported (Qdrant lacks it; the generator raises the message), not-applicable (cannot occur for Qdrant). Rows marked "generation pending" are native in Qdrant but not generated yet; the generator raises "... has no Qdrant mapping yet" for them. Runtime calls go through `vecdsl_qdrant_runtime.py`, `vecdslQdrantRuntime.ts` or `QdrantRuntime.java`; the Java runtime uses the gRPC SDK and calls REST for what gRPC lacks (snapshot recovery, optimization progress, collection updates and named vectors as JSON, shard keys, collection info). References point to the sources at the pinned tags; the OpenAPI operation or schema is named in parentheses.
