# vecDSL coverage: MongoDB

MongoDB 9.0.4 with mongot (`mongodb/mongodb-atlas-local:9.0.4`, a single-node replica set with MongoDB Search and Vector Search, port 27017 on 127.0.0.1, authentication on), Python `pymongo` 4.20.0 to <4.21, TypeScript `mongodb` 7.9.0, Java `org.mongodb:mongodb-driver-sync` 5.14.0 with Gson 2.13.2 (versions checked on 2026-11-12). Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (a database command, aggregation stage, index type or schema keyword MongoDB offers for the construct), concealed (commands, pipeline stages or runtime logic that compose MongoDB features into the exact vecDSL semantics), unsupported (MongoDB, the Atlas Local deployment or the Community license tier lacks it; the generator raises the message), not-applicable (cannot occur for MongoDB). Rows whose notes start with "generation pending" are native or concealed in MongoDB but not generated yet; they raise "... has no MongoDB mapping yet". Every command, index definition, filter and aggregation pipeline is built by the generator (`MongodbStatements.xtend`, `MongodbSchema.xtend`, `MongodbFilter.xtend`, `MongodbCommands.java`) and sent by `vecdsl_mongodb_runtime.py`, `vecdslMongodbRuntime.ts` or `MongodbRuntime.java`, so the Python, TypeScript and Java programs send the same commands. References point to the MongoDB documentation, to the mongot sources at the tag v1.70.1 (its search index JSON schemas included) and to the MongoDB issue tracker.
