# vecDSL coverage: pgvector

PostgreSQL 18 with pgvector 0.8.7 (`pgvector/pgvector:0.8.7-pg18-trixie`, port 5432, data in the named volume on `/var/lib/postgresql`), Python `psycopg[binary]` 3.3.8 to <3.4, TypeScript `pg` 8.23.1, Java PostgreSQL JDBC 42.7.14 with Gson 2.13.2 (versions checked on 2026-11-11). Rows are generated from `model/generated/VecDSL.ecore`: every concrete Method, Concept, AlterOperation and ExtensionItem class, then every structural feature of each Method class. Status: native (one SQL statement or catalog query PostgreSQL offers for the construct), concealed (SQL that composes PostgreSQL features into the exact vecDSL semantics), unsupported (PostgreSQL and the pgvector image lack it; the generator raises the message), not-applicable (cannot occur for pgvector). Rows whose notes start with "generation pending" are native or concealed in PostgreSQL but not generated yet; they raise "... has no pgvector mapping yet". The SQL text is built by the generator (`PgvectorSql.java`, `PgvectorQueries.java`) and executed by `vecdsl_pgvector_runtime.py`, `vecdslPgvectorRuntime.ts` or `PgvectorRuntime.java`, so the Python, TypeScript and Java programs send identical statements. References point to the PostgreSQL 18 documentation and to the pgvector sources at the tag v0.8.7.
